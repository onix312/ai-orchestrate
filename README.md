# ai-orchestrate

Локальный, ограниченный по вызовам оркестратор для Codex CLI. Он выбирает стартовый уровень **без отдельного LLM-запроса**, запускает Codex, проверяет результат локальными командами и при необходимости повышает уровень. По умолчанию — один недорогой проход, без Jev-router и без независимого ревью.

## Почему токены улетали и что изменилось

Старая схема каждый раз звала Jev для маршрутизации, автоматически делала до четырёх запусков Codex, повторно отправляла задачу и вывод проверок, а после успеха вызывала Jev ещё раз. При этом реальный расход Codex не показывался.

Теперь:

- локальный роутер бесплатен; Jev включается явно через `--router jev`;
- по умолчанию выполняется **одна** попытка Codex (`--max-attempts 1`), уровень не поднимается автоматически после успешных проверок;
- дополнительный независимый ревьюер запускается только с `--review`;
- Codex запускается в режиме JSONL, поэтому программа показывает фактические `input / cached input / output` токены, если их сообщает установленная версия CLI;
- usage-лог содержит только время, модель, роль и числа токенов — без задачи, diff и ключей;
- есть ограничения на суммарный текст промптов, число вызовов и следующие вызовы после достижения учтённого бюджета.

Ни один внешний оркестратор не может честно обещать жёсткий предел токенов для активного хода Codex, если CLI не предоставляет upstream hard limit. Ограничители ниже прекращают **следующие** обращения; уже начатый ход может превысить бюджет.

## Быстрый старт

Нужны Python 3.10+, Git и установленный Codex CLI с активным входом:

```bash
codex --version
codex login status
python -m ai_orchestrate doctor
```

Перейдите в каталог проекта и запустите задачу, указав реальную обязательную проверку:

```bash
python -m ai_orchestrate run "Добавь поиск по названию и тесты" \
  --repo "C:/work/my-project" \
  --check "python -m unittest discover -s tests"
```

В PowerShell используйте однострочную форму этой команды: `python -m ai_orchestrate run "Добавь поиск по названию и тесты" --repo "C:/work/my-project" --check "python -m unittest discover -s tests"`. В качестве `--check` укажите команду, которая действительно установлена и подходит целевому проекту, например `pytest -q`, `npm test` или `ruff check .`.

Перед запуском проверьте маршрут без вызова моделей:

```bash
python -m ai_orchestrate run "Короткое описание задачи" \
  --repo "C:/work/my-project" \
  --check "python -m unittest discover -s tests" \
  --dry-run
```

Для dry-run нужны существующий чистый Git-репозиторий и доступная команда `--check`. Сам dry-run не вызывает Jev/Codex и не меняет файлы.

## Визуальная панель оркестрации

Запусти локальный Python-интерфейс из корня проекта:

```bash
python -m ai_orchestrate ui
```

По умолчанию сервер доступен только на `127.0.0.1:8765`, а выбирать можно каталоги внутри текущей рабочей области. Если репозиториев несколько, задай область явно: `python -m ai_orchestrate ui --workspace-root ~/work`. Символические ссылки и пути за пределами этой папки отклоняются.

В режиме **Полный цикл** один экономный вызов объединяет роли аналитика и архитектора, затем отдельно работают выбранный исполнитель, локальные проверки и read-only ревьюер. Исправления ограничены настройками. Обычно это 3 вызова Codex, а максимально возможное число зависит от лимита вызовов и исправлений (при значениях по умолчанию — до 5). В режиме **Бережливый** по умолчанию один вызов исполнителя и проверки; дополнительных этапов планирования и ревью нет. Локальные тесты не расходуют модельные вызовы. Jev добавляет отдельный внешний запрос для триажа и не входит в лимит вызовов Codex или Codex usage ledger.

Перед запуском панель показывает число потенциальных вызовов, уже учтённый дневной usage, лимиты текста промптов и токенов, модельный маршрут и предупреждение о Jev. В раскрываемой библиотеке панели можно посмотреть готовые промпты аналитика, архитектора, разработчика, frontend/backend-инженеров, тест-инженера, технического писателя и ревьюера; исполнителя выбирают в форме, остальные роли полного цикла подключаются автоматически. После запуска видны реальные входные/выходные токены Codex (если установленный CLI передал telemetry), события ролей, команды, проверки, файлы и решение Jev. Цена в евро намеренно не оценивается: она зависит от тарифа и биллинга провайдера. Ограничение токенов остановит следующие вызовы, но не прервёт уже начатый ход модели; это не hard cap аккаунта. Скрытые рассуждения модели не запрашиваются и не отображаются.

Для доверенного браузерного preview можно привязать сервер к внешнему интерфейсу:

```bash
python -m ai_orchestrate ui --host 0.0.0.0 --port 8765 --workspace-root ~/work
```

**Сервер не имеет встроенной аутентификации.** Используй `0.0.0.0` только в доверенной приватной среде: доступ к панели разрешает запуск Codex и указанных локальных проверок в пределах выбранной рабочей области.

## Контроль расходов

```bash
# Показать суммарное использование Codex, известное этому инструменту
python -m ai_orchestrate usage

# Максимум две попытки кода: после ошибки следующий проход поднимет уровень
python -m ai_orchestrate run "Исправь обработку ошибок" \
  --repo "C:/work/my-project" \
  --check "pytest -q" \
  --max-attempts 2 \
  --max-model-calls 2 \
  --max-run-tokens 30000 \
  --daily-token-budget 60000

# Добавить отдельного read-only ревьюера (это дополнительный вызов)
python -m ai_orchestrate run "Добавь валидацию API" \
  --repo "C:/work/my-project" \
  --check "pytest -q" \
  --review
```

Основные ограничения:

- `--max-attempts` — число проходов, которые могут менять код; по умолчанию `1`, максимум `5`.
- `--max-model-calls` — жёсткий предел числа вызовов Codex вместе с ревьюером. Если не указан, рассчитывается по числу попыток и наличию `--review`.
- `--prompt-token-budget` — приблизительный лимит текста, который сам оркестратор отправит Codex во всех проходах; по умолчанию `12000`. Это оценка UTF-8-размера, **не** точный токенизатор и не включает системный контекст, файлы, вызовы инструментов или ответ модели.
- `--max-run-tokens` и `--daily-token-budget` используют usage, сообщённый Codex и записанный в локальный ledger. После достижения лимита новые вызовы не запускаются. Активный вызов может превысить предел; это не заменяет лимиты аккаунта или провайдера. Usage сторонних процессов и вызов Jev не учитываются.
- `--usage-log PATH` позволяет задать свой путь к JSONL-файлу. По умолчанию: `~/.ai-orchestrate/usage.jsonl` (в Windows — в домашнем каталоге пользователя); тот же путь можно задать через `AI_ORCHESTRATE_USAGE_LOG`.

В отчёте `input_tokens` уже включает `cached_input_tokens`; к input их повторно не прибавляют. Если Codex CLI не вернул usage-событие, фактический расход будет показан как недоступный, и запись не попадёт в ledger.

## Маршрутизация и модели

- `--router local` — по умолчанию. Простая локальная эвристика направляет небольшие задачи в `SMALL`, более широкий scope — в `MEDIUM`, а запросы с маркерами безопасности/миграций/архитектуры — в `HIGH`. Это не LLM и не дополнительный токеновый вызов.
- `--lane SMALL|MEDIUM|HIGH|ESCALATE` вручную задаёт первый уровень и не обращается к router.
- `--router jev` — опциональная удалённая маршрутизация через TypeSafe Jev; требует `TYPESAFE_API_KEY`, отправляет Jev текст задачи и расходует отдельный вызов, который не виден в Codex usage. Не используйте её, если не хотите отправлять задачу этому сервису.
- По умолчанию уровни используют `gpt-6-luna` с усилием `low / medium / high`; после неудачных попыток уровни повышаются, последним — `gpt-6-sol / high`. Имена моделей можно переопределить переменными `AI_ORCHESTRATE_LUNA_MODEL` и `AI_ORCHESTRATE_SOL_MODEL`; они должны быть доступны в вашей конфигурации Codex.
- При `--review` ревьюер по умолчанию выбирается из второй настроенной модели (или наоборот, если исполнитель уже использовал Sol). Переопределение: `--review-model MODEL` или `AI_ORCHESTRATE_REVIEW_MODEL`. Ревьюер работает в `read-only` sandbox, а его результат проходит только при первой строке `PASS`.

Примеры dry-run с явным уровнем:

```bash
python -m ai_orchestrate run "Быстрый локальный фикс" --repo ./project --check "pytest -q" --dry-run --lane SMALL
python -m ai_orchestrate run "Сложная миграция" --repo ./project --check "pytest -q" --dry-run --lane HIGH
```

## Безопасность и границы

- Целевой Git-репозиторий должен иметь хотя бы один коммит и чистое состояние, включая untracked-файлы. Сначала сохраните свою работу отдельно.
- `--check` обязателен; успешность задачи не выводится только из ответа модели.
- Codex получает `workspace-write` только на время запуска; ревьюер — `read-only`. Оркестратор не коммитит и не отправляет изменения.
- `TYPESAFE_API_KEY` и `OPENROUTER_API_KEY` удаляются из окружения дочернего процесса Codex. Не помещайте секреты в текст задачи; Codex и выбранный провайдер всё равно могут обрабатывать содержимое рабочего репозитория.
- Ledger по умолчанию локальный и не содержит запросов или diff. Не коммитьте его и не указывайте приватный путь как публичный артефакт.
- `git diff`/статус используются для read-only ревью; перед коммитом сами просмотрите изменения.

## Проверки проекта

```bash
python -m unittest discover -s tests -v
```

Живой вызов Codex/Jev зависит от вашего CLI, доступа к моделям и ключей; юнит-тесты сетевых запросов не делают.
