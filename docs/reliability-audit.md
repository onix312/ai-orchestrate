# Аудит надёжности ai-orchestrate

Дата: 2026-10-02. Проверка кода, локальных Git/worktree-сценариев, HTTP-обработчиков,
API-цикла и контроллера панели. Реальные платные запросы и публикация в GitHub не выполнялись.

## Главный вывод

Проблема была не только в отображении чата. Несколько путей могли ошибочно объявлять
задачу успешной или сохранять старое разрешение на слияние после изменения файлов.
Исправления усиливают существующую архитектуру, без замены проекта новым фреймворком.

## Исправлено

| Область | Дефект | Изменение |
|---|---|---|
| История Codex | `--ephemeral` отключал сохранение CLI-сессий | Сессии сохраняются, в ленте есть ID и `codex resume <ID>` |
| Выбор модели | Заводские настройки навязывали конкретные Luna/Sol ID, доступность которых не проверялась | Пустое значение использует настройки Codex CLI; прежние заводские ID мигрируют в пустые |
| Ошибки Codex | Ошибка из JSON могла потеряться в общей фразе, а нулевой exit скрывал `turn.failed` | Ошибка сохраняется в результате; `turn.failed` не считается успехом даже при exit 0 |
| Итог задачи | UI видел `run.completed` ещё до commit и проверки merge gates | Вложенный workflow больше не завершает всю задачу раньше времени |
| API-цикл | Исчерпание токенов возвращало exit 0; промежуточный текст маскировал исчерпание раундов | Лимиты, пустые/оборванные ответы и неизвестный usage при бюджете блокируют успешное завершение |
| API-инструменты | JSON-массив вместо объекта аргументов мог обрушить цикл | Проверка типов и диагностируемая ошибка инструмента |
| API-отмена | Между инструментами одного ответа не проверялась отмена; инструменты после `finish` могли продолжать запись | Проверки отмены/дедлайна перед каждым инструментом; `finish` останавливает обработку |
| API-учёт | Успешные раунды терялись из результата при следующей сетевой ошибке | Известный расход сохраняется; HTTP timeout ограничен остатком времени этапа |
| API-адреса | Провайдер и «локальность» определялись по подстроке URL | Точный разбор hostname, HTTPS для провайдеров, явный список локальных хостов |
| Ключи API | Локальный или чужой endpoint мог получить сохранённый OpenAI key | Локальные модели работают без ключа; незнакомые внешние хосты отклоняются; redirect не переносит Authorization |
| Команды API-модели | Список запрещённых фрагментов выдавался за защиту рабочего окружения | Произвольное выполнение команд модели отключено; пользовательские проверки выполняются отдельно |
| Git metadata | Файловые инструменты могли записать `.git` или обратиться к нему через внутренний symlink | Доступ к Git metadata запрещён |
| Патчи | Ответ применялся частично до обнаружения ошибки в следующем файле | Сначала проверяется весь пакет, при ошибке записи выполняется откат с диагностикой его ошибок |
| Парсер патчей | Незакрытые блоки могли обрезать файл; несколько hunks склеивались; первый неоднозначный контекст принимался | Строгие закрывающие маркеры, отдельные hunks, отказ при неоднозначности/повторах путей |
| Мост ChatGPT | Отвергнутый ответ или новые падающие тесты могли оставить старое разрешение на merge | Разрешение отзывается до записи, ошибки и отмена оставляют задачу неготовой |
| Ревью моста | Полный режим обходил независимого ревьюера | Повторные тесты и новое read-only ревью; никаких дополнительных прав записи модели |
| Бюджеты моста | Ручной повтор мог начать новый полный бюджет | Повторное ревью использует остаток лимитов той же задачи; дневной ledger сохраняется |
| Конкурентность | Два применения ответа или применение одновременно с merge/discard | Операция резервирует задачу и блокирует конкурирующие действия |
| Подготовка промпта | Кнопка сборки промпта повторно выполняла команды, хотя ожидалась операция чтения | Используется сохранённая информация о проверках, сборка сама тесты не запускает |
| Проверенный код | Файлы могли измениться между тестами, ревью и commit | Digest содержимого сверяется перед commit и после hooks; изменения блокируют слияние |
| HEAD задачи | Самостоятельный commit модели мог исчезнуть из diff и выглядеть как отсутствие изменений | Неожиданное изменение HEAD/ветки отклоняется, а не автоматически принимается |
| Merge | Использовалась подвижная ветка вместо проверенного commit | Повторная проверка чистоты/HEAD; локальный merge по SHA; GitHub `--match-head-commit` |
| Секретные имена | Текстовый porcelain неправильно разбирал quoted/необычные имена и переименования | NUL-разделённый формат, проверка обоих имён при rename |
| Worktree | Базовый SHA мог быть прочитан уже после перемещения исходного ref | Сначала фиксируется SHA, затем worktree создаётся от него |
| Удаление | Ошибка очистки поглощалась, после неё сообщалось об успешном discard | Ошибка видна пользователю; успешное удаление отключает повторную кнопку |
| Автоочистка | Force-cleanup мог удалить новые незакоммиченные файлы после сетевого merge | Автоматическая очистка не использует force для каталога; явный discard остаётся подтверждаемым разрушительным действием |
| Вывод тестов | `communicate()` накапливал весь stdout | Потоковый ограниченный хвост вывода; тест на 8 МБ логов |
| Проверки процессов | На Windows не адаптировались `.cmd`/`.bat`; фоновые POSIX-потомки могли пережить проверку | Разрешение executable и cmd shim; завершение POSIX process group |
| Окружение проверок | Проверки получали ключ провайдера и GitHub token | Из окружения проверок исключены известные ключи AI/GitHub; авторизация самого Codex через OpenAI key остаётся поддержанной |
| Git snapshot | Сравнение `base..HEAD` не включало незакоммиченные правки; untracked symlink мог читать внешний файл | Сравнение с рабочей копией; внешние symlink-цели не читаются |
| Автонастройка | Для локального merge могла подставляться чужая ветка из origin/HEAD | В локальном режиме выбирается открытая ветка |
| Панель | Refresh терял текущую задачу; единичная ошибка сети прекращала polling | Восстановление активной/последней задачи и повторный опрос |
| История панели | Не было способа снова открыть старую задачу с сохранённым worktree | Кнопка открытия ещё доступных запусков; путь worktree в журнале; незакрытые worktree не вытесняются из памяти по лимиту обычной истории |
| Настройки панели | Изменения во время запроса сохранения могли потеряться | После текущего сохранения отправляется ожидающее обновление |

## Изменения совместимости

- Пустые модели Luna/Sol теперь допустимы. Если нужны конкретные модели, задай их явно.
- Произвольные удалённые OpenAI-compatible адреса в панели **не поддерживаются**:
  сохранённые ключи привязаны к известным провайдерам. Локальные Ollama/LM Studio остаются.
- `run_command` для API-модели отключён. Codex CLI и пользовательские проверки не удалены.
- В полном режиме мосту нужен доступный независимый ревьюер и оставшийся бюджет.
  Бесплатное ручное исправление без вызова модели возможно в экономном режиме,
  но успешные пользовательские проверки всё равно обязательны.
- Мост требует закрытые fenced-блоки файлов или завершённые поддерживаемые патчи.
  Он намеренно не является универсальным парсером всех вариантов diff/apply_patch.
- Автоматическая проверка изменений в submodule-каталогах сейчас блокируется явной ошибкой.

## Проверки

```sh
python -m compileall -q ai_orchestrate tests
python -m unittest discover -s tests
node tests/dashboard-regression.cjs
git diff --check
```

Результат последнего полного прогона: **151 Python-тест прошёл**.
Отдельно прошли JS-регрессии контроллера: восстановление задачи, ошибка сети,
состояние ожидания merge, исчезновение задачи после restart, очередь сохранения настроек.
JS проверен в минимальном DOM, а не в полноценном браузере.

Python-тесты включают настоящие временные Git-репозитории/worktree, локальные HTTP-серверы,
неуспешные проверки, ошибки удаления, устаревшие HEAD, ограничения бюджетов, отмену,
частично неверные ответы, несколько hunks и откат после ошибки записи.
Все модельные ответы и GitHub-публикации в тестах подменяются.

## Что не следует считать решённым

1. **Перезапуск Python-сервера.** Очередь задач и события остаются в памяти. Ветки/worktree
   сохраняются в Git, журнал даёт путь, но безопасного автоматического восстановления
   исполнения и прежнего разрешения на merge пока нет. Оно намеренно не имитируется.
2. **Изоляция машины.** Worktree — не контейнер. Пользовательские проверки и Git hooks
   исполняют локальный код. Не запускай таким способом недоверенные репозитории/PR.
   Для более сильной защиты нужна отдельная ОС-песочница с ограниченной сетью и mount points.
3. **HTTP-отмена модели.** Уже начатый запрос может ждать сетевого таймаута. Нельзя гарантировать
   прекращение работы/списания токенов на стороне провайдера.
4. **Бюджет аккаунта.** Локальный ledger — не биллинг провайдера и не межпроцессный резерв бюджета.
   Не запускай одновременно несколько серверов/CLI с одним профилем, рассчитывая на строгий общий лимит.
5. **Крах во время патча.** Валидация и откат защищают обычные ошибки, но не дают транзакции
   между несколькими файлами при выключении питания или аварийном завершении процесса.
6. **Конкурирующие внешние редакторы.** Digest и HEAD-проверки закрывают обычные изменения
   между этапами, но не являются OS-блокировкой против намеренно гоняющегося внешнего процесса.
7. **GitHub auto-merge.** Проверенный SHA закреплён при запросе merge. Будущие изменения
   удалённого PR после постановки в очередь регулируются GitHub branch protection;
   локальная панель не является постоянным монитором такой очереди.
8. **Реальная совместимость окружения.** Не проверялись доступные модели/кредиты конкретного
   пользователя, GUI Codex, реальные GitHub protections, Windows-процессы и браузерная вёрстка.
   Локальная CLI-сессия не означает создание облачного чата Codex.
9. **Локальный HTTP-сервер.** Пользовательская аутентификация не добавлена. Сервис предназначен
   для loopback или защищённого preview, не для публикации в недоверенную сеть.

## Как проверить у себя после обновления

1. Не удаляя старую рабочую ветку, останови предыдущий сервер панели и запусти обновлённый.
2. Выполни `python -m ai_orchestrate doctor`, проверь `codex login status`.
3. Оставь поля моделей пустыми либо введи доступные model ID.
4. Выбери небольшой доверенный проект, экономный режим и реальную команду проверки.
5. Запусти небольшую задачу; найди событие создания сессии и её ID.
6. Обнови страницу: текущая задача должна восстановиться, пока сервер жив.
7. Проверь diff, результаты тестов и только затем подтверждай слияние.

Старые запуски с `--ephemeral` вернуть в историю Codex нельзя. Существующую ветку
`ai-orchestrate/task-1d965d13f5d1` этот аудит не удаляет и не сливает.
